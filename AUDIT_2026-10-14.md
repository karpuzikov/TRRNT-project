# TRRNT-project audit - 2026-10-14

**TL;DR:** No secrets, MIT license, all 23 Python scripts parse. The Organizer's test suite had never been run on Python; its first run found 3 stale tests (fixed in PR #2). The Duplicate Edition Analyzer had no tests (added in PR #3, which also records 3 matching gaps). Main open risks are unverified downloads and a weak self-update check in the older tools.

Scope: commit `91662df` of `main`. Static review plus test execution on Linux/Python 3.13. Not covered: Windows GUI/WebView2, `refalac64`/`flac`/AudioChecker runs, live MusicBrainz lookups, real audio, and the internal logic of the 13,000-line Duplicate Edition Analyzer beyond the functions tested in PR #3.

## Findings

### Security / supply chain

| # | Finding | Severity | Status |
| --- | --- | --- | --- |
| 1 | Duplicate Edition Analyzer self-update fetches the EXE and its `.sha256` from the same GitHub release. This detects corruption but not a tampered/hijacked release; there is no signature. | Medium | Open |
| 2 | Analyzer downloads FFmpeg (gyan.dev "latest") and Chromaprint with `urlretrieve` + `extractall`, no hash check. The Organizer already pins SHA-256, allowlists hosts and extracts safely. | Medium | Open |
| 3 | ALAC Conversion Automation v0.2 downloads the latest qaac release (first ZIP asset) with no hash check, then runs `refalac64.exe`. It also deletes source files after conversion (single files: after decoded-PCM comparison; CUE-split path not verified in this audit). Deletion is not mentioned in the docs. | Medium | Open |
| 4 | Runtime `pip install` into a user-writable folder placed first on the import path (Organizer: version-bounded; Analyzer: `heybrochecklog` pinned to a commit). Windows-only. | Low | Open |
| 5 | Analyzer loads `pickle` session files from its own temp folder. Only a risk if another process can write there. | Low | Open |

### Correctness

| # | Finding | Severity | Status |
| --- | --- | --- | --- |
| 6 | `identity_title` drops accented letters instead of folding them: `"Déjà Vu"` -> `djvu`, `"Deja Vu"` -> `dejavu`. The same song spelled both ways gets different identities (this title exists in the INNA library in several spellings). | Medium | Open - `expectedFailure` test in PR #3 |
| 7 | Cyrillic/CJK titles normalize to an empty identity, so they never match by title. Matching is still decided by audio, so this is a missed safety gate, not a false merge. | Low-Medium | Open - `expectedFailure` test in PR #3 |
| 8 | `"Song - Remastered 2009"` keeps the year in its identity while `"Song (2011 Remaster)"` does not. | Low | Open - `expectedFailure` test in PR #3 |
